ВАРИАНТ 17. ИНСТРУКЦИЯ ДЛЯ WINDOWS

1. УСТАНОВИТЕ ПРОГРАММЫ
Python: https://www.python.org/downloads/windows/
Можно установить официальный Python install manager. После установки откройте
PowerShell и выполните py install 3.13. Эта команда относится к новому manager.
Если Python уже установлен и команда py --version работает, переустанавливать
ничего не нужно: для проекта достаточно Python 3.10 или новее.
Git: https://git-scm.com/install/windows
Установите Git с обычными настройками. После установки закройте и снова откройте
терминал, чтобы команда git стала доступна.
Редактор по желанию: https://code.visualstudio.com/
Для запуска проекта редактор не обязателен.

2. РАСПАКУЙТЕ АРХИВ
Правая кнопка на ZIP -> Извлечь всё.
Откройте папку devops-variant17, в которой виден grades.py.
Не работайте прямо внутри ZIP.
Нажмите на адресную строку Проводника, напишите powershell и нажмите Enter.
Все следующие команды вводите в этом окне, по одной строке.

3. ПРОВЕРЬТЕ УСТАНОВКУ
py --version
git --version
Если команда не найдена, переоткройте терминал после установки.
Если ошибка осталась, отправьте её текст в чат.

4. ЗАПУСТИТЕ ПРИЛОЖЕНИЕ
py grades.py
Когда программа попросит оценки, введите: 80 90 100
Нажмите Enter. Ожидается: Средний балл: 90.00

5. ЗАПУСТИТЕ СБОРКУ И ТЕСТЫ
py -m pip install -r requirements.txt
py -m compileall -q grades.py tests
py -m unittest discover -s tests -v
Первая команда не устанавливает сторонних пакетов: они не нужны.
Вторая при успехе может ничего не вывести — это нормально.
Третья должна показать Ran 8 tests и OK. Сделайте скриншот.

6. СОЗДАЙТЕ ПУСТОЙ РЕПОЗИТОРИЙ
Откройте https://github.com/new в своём аккаунте.
Repository name: devops-variant17
Выберите Public, если готовы открыть учебный код всем, либо Private.
Для Private преподавателю потребуется доступ.
Не добавляйте README, .gitignore и лицензию: файлы уже есть в проекте.
Нажмите Create repository.
Скопируйте HTTPS-адрес репозитория. Он выглядит так:
https://github.com/ВАШ_ЛОГИН/devops-variant17.git

7. СОЗДАЙТЕ ЛОКАЛЬНУЮ ИСТОРИЮ И ЗАГРУЗИТЕ КОД
В том же PowerShell выполните:
git init
Затем задайте имя и email автора только для этого проекта.
Замените текст внутри кавычек своими данными:
git config user.name "Ваше имя"
git config user.email "Ваш email GitHub"
Можно использовать noreply-email из GitHub Settings -> Emails.
Далее:
git add .
git commit -m "Add Python app, tests and CI"
git branch -M main
Теперь выполните следующую команду, заменив ВАШ_ЛОГИН своим логином:
git remote add origin https://github.com/ВАШ_ЛОГИН/devops-variant17.git
git push -u origin main
Если откроется окно входа GitHub, войдите в аккаунт через браузер.
Не отправляйте пароли или токены в чат.
Если ошибка — не вводите команды force: пришлите текст ошибки.

8. ПОСМОТРИТЕ АВТОМАТИЧЕСКУЮ ПРОВЕРКУ
Откройте репозиторий на GitHub -> Actions -> Python CI -> последний запуск.
Дождитесь завершения. Ожидаются зелёные Build и Test.
Откройте Build -> Build - compile Python files: проверьте успех шага.
Откройте Test -> Run unit tests: найдите Ran 8 tests и OK.
Зелёный результат нужно проверить реально; локальная проверка не заменяет GitHub.
Если запуск красный, откройте красный шаг и пришлите его сообщение.
Если Actions отключены настройками аккаунта/организации, сначала включите их
или используйте личный репозиторий с разрешёнными Actions.

9. ПОКАЖИТЕ ПОВТОРНЫЙ ЗАПУСК ПОСЛЕ PUSH
Откройте README.md через Блокнот или VS Code.
Добавьте строку: Учебный проект по дисциплине «Прикладные аспекты DevOps».
Сохраните. В PowerShell:
git add README.md
git commit -m "Update project description"
git push
В Actions появится новый запуск. Дождитесь результата.

11. ЧТО СКАЗАТЬ НА ЗАЩИТЕ
Программа вычисляет средний балл и отклоняет некорректные оценки.
Unit-тест — автоматическая проверка отдельной функции.
Git хранит историю изменений, GitHub хранит удалённый репозиторий.
Commit фиксирует изменения локально, push отправляет их на GitHub.
После push GitHub Actions выполняет Build, затем Test.
Build компилирует Python в байт-код, Test выполняет 8 проверок.
needs: build запрещает запуск Test, если Build завершился ошибкой.
CI — автоматическая интеграция и проверка изменений.
В этой работе нет развёртывания на сервер: реализован требуемый базовый CI.
